# تحديث منصة NEO PULSE HUB

## ما تم توحيده

أصبح `products.json` هو الكتالوج العام الأساسي للواجهة الثابتة، ويُستخدم كذلك كسياق افتراضي للمنسق المركزي في `backend/ai_orchestrator.py`. لا تعتمد صفحة المنتجات العامة على تسجيل دخول المستخدم، بينما تبقى عمليات الإدارة والمساعد الداخلي محمية. ويستخدم خادم React المنسق `server/ai-orchestrator.ts` لمسار Neo Copilot بدلاً من تكرار بناء سياق المنتجات داخل المسارات.

## طبقة الذكاء الاصطناعي

تمر عمليات الذكاء الاصطناعي الجديدة عبر `backend/ai_orchestrator.py`. ويستعمل المنسق محرك `backend/ai_engine.py` الذي يحاول Gemini ثم Groq ثم OpenAI، مع إجابات محلية عند غياب المفاتيح أو فشل الاتصال. لا تُنشأ أسعار أو تقييمات وهمية عند غياب البيانات.

## الكتالوج

يُستخدم `scripts/normalize_catalog.py` لفحص الكتالوج وتنظيفه بشكل متكرر. الأداة:

- تتحقق من وجود المعرّف والاسم والسعر والتقييم والفئة.
- تحوّل القيم الرقمية غير المتسقة إلى أرقام.
- تزيل التكرار في المعرفات والأسماء.
- تحافظ على المعرض والصورة الأساسية.
- تستخدم صورة placeholder واضحة عند غياب الصورة بدلاً من اختلاق صورة لمنتج حقيقي.

تشغيل الفحص محلياً:

```bash
python3 scripts/normalize_catalog.py --check
```

تطبيق التنظيف:

```bash
python3 scripts/normalize_catalog.py --write
```

## النشر والتحديث الدوري

النطاق `neo-pulse-hub.it.com` مرتبط حالياً بـ GitHub Pages من جذر فرع `main`. لذلك فإن تعديل الملفات العامة في المستودع هو مصدر النشر الفعلي. يثبت `deploy.yml` صحة ملف `CNAME`، ويفحص الكتالوج، ويشغّل اختبارات محرك AI، ويبني تطبيق React قبل اعتبار التغيير صالحاً.

يعمل `catalog-sync.yml` كل ست ساعات وعند تشغيله يدوياً. في هذه المرحلة هو تحديث حتمي وآمن للبيانات المحلية فقط؛ لا يستخدم مولدات mock أو أسعاراً عشوائية ولا يستدعي واجهات خارجية دون مفاتيح ومصدر موثوق. أما توليد المقالات فيبقى في سير العمل اليومي المنفصل.

## ما يحتاج إعداداً خارج GitHub

لا يستطيع GitHub Pages تشغيل Express أو قاعدة بيانات MySQL أو Webhook بصورة دائمة. لذلك تبقى واجهة HTML العامة هي نسخة الإنتاج الحالية، بينما تطبيق React/Server يحتاج استضافة Node كاملة إذا أريد جعله المصدر العام للنطاق. بعد توفير استضافة Node، يجب توجيه النطاق إليها ثم نقل مسار النشر من GitHub Pages إلى تلك الاستضافة، مع إبقاء GitHub Actions للاختبارات والبناء.

```bash
npm exec --yes pnpm@10.15.1 -- install --frozen-lockfile
npm exec --yes pnpm@10.15.1 -- run build
```
